1. **Who wrote it:** in this repo the HRIS server is an in-repo stand-in (`backend/mcp/servers/hris_server.py`, ~100 lines, no network code); a real People Ops or third-party HRIS connector is code we did not write and must be pinned to a reviewed version before it runs inside the agent's trust boundary.
2. **What it can reach:** the stand-in reads one file (`HRIS_DATA_PATH`: grade band and accrued leave by employee id) and is launched with a minimal environment, so it cannot see `GROQ_API_KEY` or the Qdrant key (enforced by a test); a real connector reaches whatever its credential allows, which may include salary-adjacent fields.
3. **What it logs:** the stand-in writes only error lines to stderr and no employee data; the host writes one audit line per call (caller, tool, employee id, attempts, outcome, hashed session) to `traces/mcp_audit.jsonl` and never the returned values.
4. **What a stolen token could do:** the stand-in has no token (stdio, no network listener); with a real connector a stolen token could enumerate every employee id and read each grade band and leave balance, so scope the token to these two read-only calls, give it a short TTL, rate-limit it and alert on id scans.
5. **Ship or don't:** ship the read-only stand-in behind the minimal-environment launch; do NOT ship a third-party connector until its source is reviewed and pinned, its token is scoped to `get_grade_band` and `get_leave_balance` only, and the audit log is monitored.
